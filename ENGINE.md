# Движок генерации кода — как это работает

Файлы: `src/code-engine.js` (движок), `src/github-auth.js` (вход + пуш), экран «Создать» в `www/index.html` / `src/app.js`.

## Пайплайн

```
Текст задачи
    │
    ▼
detectLanguage()      — ключевые слова → python/javascript/java/kotlin/bash (по умолчанию python)
detectComplexity()    — длина текста + ключевые слова → simple/medium/advanced
    │
    ▼
buildPlan()            — короткий список шагов, показывается пользователю до генерации
    │
    ▼
generateCoreLogic()    — единственный вызов локальной модели (та же Qwen2.5-0.5B/wllama, что и в чате),
                          system-промпт просит только код, без markdown и пояснений
    │
    ▼
scaffoldFiles()         — оборачивает сгенерированную логику в мини-проект под язык
                          (package.json/requirements.txt/README.md и т. п.)
    │
    ▼
buildZip() / pushProjectToGithub()
```

Всё, кроме последнего шага (пуш в GitHub — по желанию пользователя), выполняется без единого сетевого запроса.

## Пользовательский контроль

- Язык и сложность определяются автоматически, но на экране «Создать» есть выпадающие списки для ручного переопределения (`auto` / конкретное значение).
- Пользователь не обязан ничего донастраивать — по умолчанию всё происходит без его участия после нажатия «Создать».

## Реалистичные границы

Модель — 0.5B параметров (та же, что для чата, ради единого размера APK). Это значит:

- Хорошо получаются: небольшие скрипты, утилиты, простые CRUD-заглушки, шаблонные обработчики.
- Плохо или не получится: крупные многомодульные системы, сложная бизнес-логика, код, требующий реального понимания внешних API/схем БД, которых нет в тексте задачи.
- Движок **не проверяет и не запускает** сгенерированный код — синтаксические ошибки в сложных случаях возможны, особенно на уровне "продвинутый".

## Вход через GitHub и пуш проекта

- `src/github-auth.js` реализует OAuth Device Flow: `POST /login/device/code` → пользователь вводит код на github.com → поллинг `POST /login/oauth/access_token`.
- Требует **Client ID** OAuth-приложения GitHub с включённым Device Flow (создаётся один раз в настройках GitHub пользователя, без API — это ограничение самого GitHub). Client ID вводится в приложении и сохраняется в `localStorage`.
- Device Flow endpoints не поддерживают CORS из браузера, поэтому `capacitor.config.json` включает `CapacitorHttp.enabled: true` — на Android это заставляет `fetch`/`XMLHttpRequest` идти через нативный сетевой стек, а не WebView, что убирает ограничение CORS.
- Пуш готового проекта: `POST /user/repos` (создание приватного репозитория) → `PUT /repos/{owner}/{repo}/contents/{path}` для каждого файла (Contents API, без git/SSH на устройстве).
